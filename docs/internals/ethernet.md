# イーサネットの土台

vehicle-sil 自体を直す人と、イーサネットのフレームを直接扱うプロトコルや試験を作る人向けです。フレームの型、ポートの契約、チャネル、仮想ネットワーク、SIL Kit のポートの契約を扱います。先に [architecture.md](../architecture.md)（全体の形）と [code-map.md](../code-map.md)（どこを変えるか）を読みます。ステップを回す仕組み（ホスト、ドライバー、時間の領域）は [can.md](can.md) にあり、イーサネットも同じものを使います。API はまだ変わることがあります。

- `vehicle_sil::eth` は SIL Kit に依存しません。`vehicle_sil::step` と `sim_base` だけをリンクし、`eth.boundary` が SIL Kit のヘッダーを含まないことを確かめます。
- `vehicle_sil::eth_silkit` は、`vehicle_sil::eth` のポートを SIL Kit の Ethernet のコントローラーの上に作ります（仮想時間だけ）。
- vehicle-sil はフレームの中身を解釈しません。読むのは宛先と送り元のアドレスだけで、EtherType、VLAN のタグ、payload はバイト列のまま通します。TCP/IP などのスタックは持ちません。

## 値の型

- `Frame` は、宛先のアドレスから payload の終わりまでのバイト列です（FCS を含みません）。バイトはオブジェクトの中に持ち（`Frame::kCapacity` まで。確保しません）、写すときは長さの分だけ写します。比較は長さとバイトで行います。`destination()` は 0〜5 バイト目、`source()` は 6〜11 バイト目です。
- `MacAddress` は 6 バイトのアドレスです。`parse()` は `02:00:00:00:00:01` の形（`:` か `-` で区切った 16 進の 2 桁が 6 つ）を読み、`to_string()` は小文字と `:` で書きます。順序（`<=>`）はバイトの辞書順です。
- `TimedFrame` は時刻付きのフレームです。受信では送り手のステップの時刻（時刻同期した送り手の場合。そうでない送り手は「[時刻同期に参加していない送り手](#時刻同期に参加していない送り手)」）、送信では送るステップの時刻です。

## ポートの契約（`Port`）

`vehicle_sil::can::Port` と同じ決まりです。

- `release_before(now, sink)` は、時刻が `now` より前の受信フレームを、時刻順、同じ時刻なら到着順に渡します。時刻がちょうど `now` のフレームは次の呼び出しで渡します。同じ時刻のフレームを並べ替えるのはチャネルです。
- 自分が送ったフレームは受けません。
- `send()` は同期の結果を返します（`Accepted`、`QueueFull`、`Failed`）。`kHeaderBytes`（14）より短いフレームは `Failed` です。
- `release_events_before(now, sink)` は、時刻が `now` より前の事象を同じ順で渡します。ホストは同じステップで `release_before()` より先に呼びます。

事象（`PortEvent`）は 3 種類です。

| 種類 | 意味 | 時刻 |
|---|---|---|
| `TransmitCompleted` | 送ったフレームをバックエンドが送信した | バックエンドが確認した時刻 |
| `TransmitFailed` | `send()` が受け付けたフレームを、バックエンドが送らなかった（リンクが落ちている、コントローラーが動いていない、捨てた） | バックエンドが知らせた時刻 |
| `ReceiveOverflow` | 受け箱が満杯で受信フレームを捨てた。`count` は捨てた数 | 捨てたフレームのうち最も早い時刻 |
| `EventOverflow` | 事象の受け箱が満杯で、送信の確認の事象を捨てた。`count` は捨てた数 | 捨てた事象のうち最も早い時刻 |

`ReceiveOverflow` と `EventOverflow` は事象の受け箱の枠を使いません（`OverflowCollector`）。送信の確認を押し出さず、受け箱が満杯でも届きます。

## チャネル（`Channel`）

アプリケーションが生のフレームを送受信する口です。`step::Member` なので、`step::Host` に載せると、ほかのメンバーと同じステップで、足した順に回ります。メンバーの関数（`begin()`、`receive(now)`、`process()`、`flush()` など）はホストのためのもので、`Channel` では private です。

1 ステップ（時刻 `now`）の動きです。

1. 受信の段: ポートが `now` より前に出したフレームのうち、絞り込みと長さの検査を通ったものを、時刻、送り元のアドレス、到着の順に並べます。ポートの事象は数えるだけです。
2. 処理の段: `on_frame()` で足したハンドラーを、フレームごとに、足した順に呼びます。
3. アプリケーションの段: `receive()` が同じフレームを同じ順に 1 つずつ返します。取らなかったフレームは、次のステップには残りません。一度でも `receive()` を呼んだチャネルでは、ステップの終わりに取らなかったフレームを `frames_not_taken` に数えます（ハンドラーだけのチャネルは数えません）。ハンドラーと `receive()` は互いに影響しません。
4. 送信の段: そのステップの `send()` のフレームを、呼んだ順に、時刻 `now` でポートに渡します。ポートが受け付けなかったフレームは数えて捨てます（キューが満杯ならそのフレームと残り全部、失敗ならそのフレーム）。出し直しはしません。

- `send()` と `receive()` は、ステップの中（ハンドラーかアプリケーション）だけで呼べます。外から呼ぶと `std::logic_error` です。ハンドラーから同じホストのほかのチャネルに送ることもできます（ゲートウェイ）。そのフレームは同じステップの送信の段で出ます。
- `on_frame()` はホストが始まる前だけです。

### 同じ時刻のフレームの順

SIL Kit では、違う送り手から同じ時刻に届いたフレームの到着の順が、スレッドの都合で決まります。チャネルは、同じ時刻のフレームを送り元のアドレス（6〜11 バイト目）の順に並べ、同じアドレスの中は到着の順のままにします（安定な並べ替え）。そのため、同じ ECU を仮想ネットワークで動かしても SIL Kit で動かしても、ハンドラーと `receive()` に渡る順が同じになります。同じアドレスの送り手が 2 つあると、その 2 つの間の順は決まりません。

### 時間

- 時刻 t のステップで送ったフレームは、受け手の「t より後に始まる最初のステップ」で届きます。伝送の時間は模擬しません。両方が 1 ms のステップなら、往復は 2 ms の仮想時間です。
- 届いたフレームの時刻は、送ったステップの時刻です（時刻同期した送り手の場合）。

### 上限（`ChannelOptions`）

| 値 | 既定 | 意味 |
|---|---|---|
| `send_capacity` | 256 | 1 ステップで `send()` が受け取るフレームの数。超えると `SendStatus::QueueFull` |
| `receive_capacity` | 1024 | 1 ステップで渡すフレームの数。超えた分は捨てて `receive_overflows` に数える。どれが捨てられるかは届いた順で決まるので、SIL Kit では決まらない。あふれは誤りとして扱う |
| `max_frame_bytes` | 1522 | 送れるフレームと、渡すフレームの最大の長さ（FCS なし）。`kHeaderBytes` から `Frame::kCapacity`（2048）まで。長い受信フレームは捨てて `frames_invalid` に数える |
| `accept` | `All` | `All` はネットワークの全部のフレーム（プロミスキャスのキャプチャと同じ見え方）。`Addressed` は `mac` 宛て、ブロードキャスト、`multicast` に挙げたアドレス宛てだけ。外したフレームは `frames_filtered` に数える |

どちらの受け箱も、生成のときに 1 回だけ確保します。ステップの中では確保しません（並べ替えは、受けた順のフレームを動かさずに、添字の配列を並べます。`eth.steps_do_not_allocate` が確かめます）。1 フレームは `Frame::kCapacity` バイトを持つので、既定の大きさでは、チャネル 1 つで約 2.5 MB、仮想ネットワークと SIL Kit のポートの受け箱は、それぞれ約 4 MB（並べ替えのための写しを含む）を使います。

### 統計（`ChannelStatistics`）

`frames_received`（渡した）、`frames_taken`（`receive()` で取った）、`frames_not_taken`（`receive()` を使うチャネルで、取らずに終わった）、`receive_overflows`、`frames_filtered`、`frames_invalid`、`frames_sent`（ポートが受け付けた）、`sends_rejected`（`send()` が断った）、`frames_dropped`（受け取ったがポートが受け付けなかった）、ポートの事象の `transmit_completed`、`transmit_failed`、`port_receive_overflows`、`port_event_overflows`（ポートが捨てた送信の確認。その分 `transmit_completed` と `transmit_failed` が少ない）です。数は増えるだけです。

## 仮想ネットワーク（`VirtualEthernetBus`）

プロセスの中のイーサネットです。SIL Kit の Network Simulator なしの Ethernet と同じく、ハブとして振る舞います。

- `attach()` ごとに 1 つのエンドポイント（`Port`）を作ります。
- 時刻 t で送ったフレームは、宛先のアドレスによらず、ほかの全部のエンドポイントに時刻 t で届きます。自分には届きません。送信の確認の事象は出しません。
- `min_frame_bytes`（既定 60）より短いフレームは、受け手に 0 で埋めて届けます。SIL Kit と同じ記録にするためです。0 にすると埋めません。
- 受け手がすでに渡した時刻より前のフレームは、`std::logic_error` で断ります（ホストを時刻の順に回していない）。`StepDriver` はこの順を守ります。
- 受け箱（`inbox_capacity`、既定 1024）があふれると、捨てて数え、`ReceiveOverflow` を出します。
- スレッド安全ではありません。1 つのスレッド（`StepDriver` のループ）から使います。

## SIL Kit のポート（`SilKitEthPort`）

時刻同期した participant の Ethernet のコントローラーの上のポートです（`TimeDomain::Virtual`）。実時間（時刻同期なし）のポートはまだありません。

- 生成のときに、受信（RX の向きだけ）、送信の確認、状態の変化のハンドラーを登録し、コントローラーを `Activate()` します。`close()` はハンドラーを外し、`Deactivate()` し、ためたものを捨てます。`close()` の後、SIL Kit はポートを呼びません。
- 受信のハンドラーは、フレームを受け箱（`StepInbox`）に SIL Kit の時刻（送り手のステップの時刻）で積むだけです。`Frame::kCapacity` より長いフレームは数えて捨てます。
- 送信は、そのステップの時刻で `SendFrame()` を呼びます。送信の確認は、Network Simulator がなければ `SendFrame()` の中で返るので、事象として積んで次のステップで渡します（チャネルをその場で呼びません）。`Transmitted` は `TransmitCompleted`、`ControllerInactive`、`LinkDown`、`Dropped`、`InvalidFrameFormat` は `TransmitFailed` で、種類ごとの数は統計にあります。`event_capacity`（既定 1024）は、1 ステップに送るフレームの数（チャネルの `send_capacity`）以上にします。あふれた確認は捨てて数え、`EventOverflow` で知らせます。
- 60 バイトより短いフレームは、受け手の SIL Kit が 0 で埋めます（送る側では埋めません）。

### 時刻同期に参加していない送り手

時刻同期に参加していない participant（実際のネットワークへのブリッジなど）のフレームには、SIL Kit は `std::chrono::nanoseconds::min()` の時刻を付けます。ポートはこの時刻をそのまま渡しません。時刻が負のフレームには、届いた時点でのこの participant の最新のステップの時刻（最初のステップの前なら 0）を付け、次のステップで渡します。そのステップの時刻に送られたフレームと同じ扱いです。どのステップで届くかは届いた時点で決まるので、決定的ではありません。数は `received_without_time` にあります。

CAN の仮想時間のポート（`SilKitCanPort`）は、この場合の時刻を寄せずに、`nanoseconds::min()` のまま渡します（次のステップで渡す点は同じです）。

### 終わりの順序

ParticipantRuntime を止める（ステップが来なくなる）、ポートを `close()` するか壊す、チャネルを壊す、ParticipantRuntime を壊す（コントローラーを持つ）の順です。

## 未確認の値

次の値は、一般の資料と SIL Kit のソースの知識によるもので、規格では確かめていません。変えられる値は、利用者が変えられるようにしてあります。

| 値 | 使う所 | 変え方 |
|---|---|---|
| 最大の長さの既定 1522 バイト（FCS なし。タグのない 1514 バイトに、タグの分の余裕を足したもの） | `ChannelOptions::max_frame_bytes` | 選択肢。上限は `Frame::kCapacity`（2048。これより大きいジャンボフレームは扱わない） |
| 最小の長さ 60 バイトへの 0 の埋め | SIL Kit の受信（上流の実装）、`VirtualEthernetBusOptions::min_frame_bytes` | 仮想ネットワークは選択肢。SIL Kit の側は変えられない |
| 先頭の 14 バイト（宛先 6、送り元 6、EtherType か長さ 2）と、アドレスのバイトの並び | `kHeaderBytes`、`Frame::destination()`、`source()`、送れる最短のフレーム | 変えられない |
| アドレスのグループの印（1 バイト目の最下位のビット）と、ブロードキャスト（全部 0xFF） | `MacAddress::is_multicast()`、`is_broadcast()`、`Accept::Addressed` | `Accept::All` なら使わない |
| 試験の EtherType 0x88B5（ローカルの実験用として知られる値）と、ローカル管理のアドレス `02:00:00:...`、`03:00:00:...` | 試験だけ | — |

## 試験

- `eth.*`（`tests/eth`、`vehicle_sil::eth` だけをリンク）: 値の型、仮想ネットワーク（ハブ、次のステップ、埋め、自分のフレーム、時刻の順、あふれ）、チャネル（ホストとドライバーの上で回ること、ゲートウェイ、同じ時刻の順、`receive()` と取らなかった数、送信の段、上限、絞り込み、事象、選択肢の誤り）。`eth.steps_do_not_allocate` は、ステップの中で確保しないことを、プロセスの全部の確保を数えて確かめます（専用の実行ファイル。数え方は J1939 の同じ試験と共通の `tests/unit/allocation_counter.hpp`）。`eth.boundary` は SIL Kit を含まないことを確かめます。
- `eth_silkit.*`: 偽のコントローラーに対するポートの試験（時刻のないフレーム、あふれた送信の確認を含む）と、プロセス内の registry で、同じシナリオの記録が仮想ネットワークと SIL Kit で一致すること（ステップ幅の組み合わせを変えて。3 つの送り手が同じ時刻に送る場合、短いフレームの埋め、ハンドラーからの返事、`receive()`、`Accept::Addressed` を含む）。ノードのアドレスは登録の順と違う順にしてあり、仮想ネットワークの側だけでも、同じ時刻のフレームがアドレスの順に並んでいることを確かめます。
